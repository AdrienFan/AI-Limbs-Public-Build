# 视觉 0.2.12 旋转换帧间隔修复

0.2.11 与 build113 的五轮桌面点击启动横屏游戏中，三轮观察成功，其中两轮 superseded_frames=1，证明上一版的帧与状态几何竞争修复已实际生效。另两轮动作成功但观察报 SCREEN_CAPTURE_UNAVAILABLE。

## 证据与发生路径

设备采集日志在 11:59:59.460、12:01:24.820 记录正常 resize 到 2176×1812；视觉错误分别在 44 ms、18 ms 后出现。此次采集日志没有停止、resize 失败或生产器异常记录，后续同会话可以正常取帧。

build113 的 resizeCapture 更新几何后清空 bufferedFrame，等待新 ImageReader 的首帧。此间 capture.active=true、producer_error=null、frame_available=false 是正常的换帧状态。0.2.11 的 requireActive 在比较几何之前合并检查 frame_available，导致已经被旋转替换的观察证据可能被误报为采集故障。旧错误未携带失败时各字段，历史状态不能逐字段还原；本轮修复针对源码明确存在、与日志时序吻合的路径，同时细分错误信息。

## 修复作用域

只修改通用视觉插件，升级 0.2.12、versionCode 18、payload v0212，继续使用 build113 和原桥。

先验证会话、采集活跃、生产器状态存在且无异常、内容可见，再比较状态与所选帧几何。点击后允许跟随且几何已改变时，返回失效证据，无论新的帧缓存是否已就绪；控制器沿用原有预算采样，清除旧返回帧并重置稳定窗口。下一轮 Host latest 读取会在原期限内等待新方向的有效缓存。

当前几何未改变但无帧仍明确失败；standalone 等待仍严格绑定原几何。停止、不可见、生产器异常及状态字段缺失不能进入换帧分支。保留 SCREEN_CAPTURE_UNAVAILABLE 前缀，分别说明采集停止、生产器状态缺失、生产器异常及当前方向无帧。没有重放点击、重新执行工具、重启采集或新增观察预算。

## 验证

- 健康的旋转空缓存使旧证据失效，新方向帧到达后才允许接纳
- 同方向空缓存在严格及跟随模式中均失败
- standalone 模式拒绝旋转空缓存
- 旋转空缓存不能掩盖停止、不可见、错误会话或生产器异常
- 复用已有稳定窗口失效及原始采样回归用例
