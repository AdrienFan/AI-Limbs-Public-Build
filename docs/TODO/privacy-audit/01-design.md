# 可行性与整体设计

## 现有架构与实际能力

以正式架构地图及实际源码为准。普通插件通过 InProcessPluginEntry 注册 capability、page、screen 和 home tile；Resident 的展示入口只注册页面，业务仍在统一的业务 owner 内执行。插件不分支判断 Host/Resident，不创建第二个后台采集 owner。

实测设备为 Android 16 / API 36。现有执行后端返回 uid 2000，说明这次连接具备非 Root Shell 能力。`pm list users` 发现主用户 0 与安全文件夹 150；后者的包查询成功返回空文本，不能据此视为已覆盖。设备已安装 Clash，未调整它的配置或连接。

基座 build121 的 `host.process@1/execute` 已绑定受控 `execute_shell`，结果包含结构化 exitCode/output，权限仍通过 Dispatcher。`host.android.package@1`、`host.android.usage@1`、持久调度及后台生存租约尚未作为普通插件可申请且完整绑定的接口开放。第一版使用现有 Shell 采集平面，不把业务塞进基座，也不调用未绑定原语。

## 技术路线选择

普通 Android 进程无法获得任意应用的完整 AppOps 记录。应用可见性、跨用户权限、网络统计授权及设备厂商的容器限制都会产生缺口。已有 Shell 是当前设备上最有价值的非 Root 采集能力；本版明确要求现有 ADB/Shizuku Shell 可用。失去该能力时报告不可观测，不申请 Root、不改权限、不换后端、不伪造零值。

不建立第二个 VpnService。Android 每用户/资料仅允许一个活动 VPN，新 VPN 会停止既有 VPN；这与当前 Clash 环境冲突。不开启 MITM、不安装证书、不解密 HTTPS/QUIC、不获取消息、联系人内容、照片、定位坐标或麦克风音频。

新的系统事实接口仍有长期价值。后续若需在没有 Shell 时提供普通应用级基础清单，应以通用、权限受控的 Package/Usage Host 原语补齐，业务继续留在插件。本轮没有虚构这些接口已经可用。

## 采集与覆盖

- 用户清单：`pm list users`。逐用户查询包与 UID，空清单/拒绝/未知格式保留为独立覆盖失败。
- 应用清单：`pm list packages --user N -U`，包含此后端可见的无界面和系统包。以 user + package 为身份，并校验 UID 的用户部分。
- 入口形态：MAIN/LAUNCHER 组件查询。无启动入口只表示一级候选；应用可能有深链接、被其他组件拉起或有非 Launcher 界面。
- 详情：限定包的 dumpsys 输出经过滤后只保留版本、系统标记、目标用户安装/启用状态及权限。不同用户的 runtime permissions 不混用。
- AppOps：记录操作模式、系统历史字段以及明确的 `(running)` 标记。拒绝时间不当成成功访问，历史访问不与当前 UID 状态拼接成后台访问。
- 运行状态：`cmd activity get-uid-state` 是一个采样点的 UID 状态，不是全天运行轨迹。
- 网络：只取 UID 统计段的未标记物理移动/Wi-Fi记录，排除 VPN 虚拟接口、TAG 明细与 VPN 调试集。预处理只输出 UID 与聚合计数，不保存订阅标识、SSID 或目的地址。
- 系统组件：额外列出 Shell 可见的 Binder 服务及无法映射到包的网络 UID。不会把这两份目录称为完整系统服务行为审计。

计数是系统历史桶的聚合，可能延迟、回退、重置或受 VPN 归因影响。首次、开机标记变化、身份变化、任何计数下降都重新建立基线。统计新增不等于采样时间窗内精确发送量，更无法确定载荷内容。共享 UID 的流量不分摊给单个包。

每个系统命令通过宿主执行，有进程超时、调用超时与输出上限；管道使用 pipefail。未知格式拒绝成为有效证据。采样失败不标成安全、不标成卸载。

## 优先级与风险是两条独立维度

一级：无启动入口的后台候选。二级：有入口且已观察到后台活动的混合候选，或入口不可观测的暂定对象。三级：有入口、尚未观察到后台活动的前台候选。不存在完整长时轨迹时，界面明确标注“候选”。

默认每 15 分钟采样，每轮一级/二级/三级最多 12/8/4 个深度对象；组内按最久未尝试者轮转，失败对象也更新尝试时间，避免持续占队首。可手动对指定应用排队采样。清单数量不等于完成详情采样数量，每个证据展示自己的时间。

- UNKNOWN：证据缺失、网络基线未就绪或采样失败。
- R0：此次完整样本未触发异常规则，不是安全认证。
- R1：新授予敏感权限的配置变化，或正在进行的敏感访问等需要用户理解的证据。
- R2：唯一 UID、采样时处于后台、系统报告敏感操作正在进行，且背景发送计数增加至少 1 MiB。它只表示需要核查的并存现象；不同时间粒度意味着不能证明上传了敏感内容。
- R3：保留给有更直接证据的严重结论，当前采集源不会自动输出。

静态权限和应用形态单独不升级为恶意风险。用户可标注预期后台活动，此标记抑制对应 R2 关联规则但不删除证据。用户知情/授权意图不能仅从系统权限推断。

## 生命周期与告警

默认关闭监测。用户启用后由插件业务 owner 的协程循环执行；禁用、卸载或宿主停止会取消协程。重挂载按保存的启用设置恢复。没有已绑定的持久 scheduler/前台服务租约，因此不承诺进程被杀、休眠或重启间隙仍能运行；历史记录挂载和停止边界。

应用页保留风险与证据，R2 待核查数量可进入现有 Attention sideband。系统通知由用户另行启用，最多每 6 小时一次，失败写入审计记录。告警不自动修改应用或网络规则。

## 用户控制与恢复

权限、后台限制及系统自带管理使用目标用户的系统应用设置入口。

插件内停用使用 `pm disable-user`，只允许主用户、非系统、独立 UID 的普通包。保护当前宿主、系统/低 UID、共享 UID、默认桌面、默认输入法、已启用的辅助功能、设备管理组件、VPN，以及无法确认身份的对象。操作前要求暂停轮询，重新查询包、版本、关键组件、运行状态和 VPN AppOps。

预检生成两分钟有效的一次性 token，界面展示具体包名与影响；执行需 token 加完整包名确认，执行前再次检查身份与关键组件。原启用状态仅允许 DEFAULT/ENABLED，恢复使用相应的 `default-state`/`enable`，不简单把所有包强制设为 enabled。

执行前持久化意图，执行后重新读取系统状态。超时/未知结果保留 pending 记录供人工核查，不自动重复写入或盲目恢复。仅允许恢复本插件持有记录、UID/版本仍一致的对象。系统包和其他用户不提供插件内停用。

## 本地隐私与审计记录

SQLite 位于插件 dataDir。没有云分析或外联代码，也不读取 Android 稳定设备标识。只保存必要的包级元数据、操作证据、统计和失败原因。日常日志不写应用采集正文；现有 Host 执行日志仍按宿主日志策略处理固定采集命令及其结果。

默认保留 30 天、最多 5000 条事件，挂载时、每轮完成及运行期间每小时清理过期事件；使用本地哈希链检测保留区间的内部不一致。数据库写权限者仍能重写全链；这不是独立签名或第三方见证。用户清除历史会保留新的清除事件，当前快照和控制恢复记录不随历史清除。

主动导出需要确认，由独立的短时后台任务分块写入手机 Download，完成路径显示在首页，包含快照和最近 200 条事件；不会自动分享。共享下载目录的可读范围较私有目录更广，确认框明确说明。完整保留历史可通过 history 游标分页读取。

## 依据与时效

2026-11-07 对设备和当前源码进行了直接只读检查。以下是一手平台资料，用于 API 的权限与归因边界；检索缓存有数周至数月延迟，因此不据其判断晚于快照的新版本发布状态：

- [包可见性](https://developer.android.com/training/package-visibility)：普通应用清单会被过滤。
- [AOSP NetworkStatsService](https://android.googlesource.com/platform/frameworks/base/+/325365b74d9d9c50b17eba0acbb3e7d6ff3a17f8/packages/ConnectivityT/service/src/com/android/server/net/NetworkStatsService.java)：UID/tag 统计、VPN 迁移及 dump 数据形态。具体 OEM 格式仍以设备证据为准。
