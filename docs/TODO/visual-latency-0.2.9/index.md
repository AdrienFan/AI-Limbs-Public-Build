# 视觉延迟归因与针对性修正 0.2.9

## 实测依据

部署版本为视觉工作台 0.2.8、基座 build112、ChatGPT 桥 0.0.30。2026-10-08 的普通 ChatGPT 页面观察，在 ALLOW 状态、不附图片时，完整取回结果仍耗时 21.528 秒。结果约 68 KB，包含 254 个节点，大量为空布局容器。

第二次仅取得首个结果耗时 3.202 秒。桥分段计时为 Host 执行 1895 ms、结果适配 44 ms、首次回传 474 ms。此前分页读取样本的手机处理约 9–31 ms，回传约 0.47–0.56 秒，每页还包含客户端与上游往返。不能将这些往返全部归为异常网络波动，也不能将 21 秒都归为截图耗时。

1800 ms 和 2500 ms 的视觉等待分别记录内部 elapsed_ms=2290 和 2936。该计时在最终预览编码和桥回传之前结束，故超额发生于手机内。源码确认每轮只把剩余预算传给取帧，之后仍采样原始数据并读取、验证会话健康，下一轮没有整轮成本预留。具体阶段分布需新版本的 timings_ms 实测，不凭源码猜测某一个阶段占了全部超额。

## 修改范围

仅视觉插件；复用既有基座能力，各桥共用。普通 observe 默认返回固定快照中的首批语义节点、明确筛选范围和续读位置。完整树仍用于分类并保留；page.inspect 继续返回全部节点，新增 page.nodes 对同一快照按需续读。全文读取及节点 ID 不变。节点复制先移除 children 再复制属性，避免逐层重复序列化子树。

等待循环记录取帧、采样、来源验证耗时，用已测最慢完整轮成本决定是否开始下一轮。剩余预算不足时保留最后一次已验证观察并等到观察期限，返回 TIMEOUT。不得把剩余静候时间当成有效稳定观察，不取消在途 Host 调用，不移除健康检查，不增加重试或降级。

这属于轮询准入预算，不能保证首轮或突然变慢的在途调用一定在期限内结束。deadline_policy=poll_admission，真实超额通过 deadline_overshoot_ms 显示。timeout_ms 不含最终编码和网络回传。

## 验证

云端执行既有单元测试和 APK 构建、能力声明一致性检查、来源版本检查、签名与产物来源记录。新增回归覆盖紧凑观察续读后无节点丢失、完整快照与文字不随页面变化、长标签预算续读、整轮成本的超时准入以及首轮可能超额。

安装后的真实收益需同页面复测：默认 observe 是否减少桥分页；等待的 deadline_overshoot_ms 和分段耗时。不能把云端构建通过描述为已经在手机上验证新版性能。
