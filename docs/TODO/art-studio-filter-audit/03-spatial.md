# 第三阶段：空间、纹理、表面与降噪滤镜

继续第二阶段的源码迭代；本阶段不构建、不部署、不推送云端。现有插件身份、工程格式、菜单动作和历史类型保持，新增实现仍由手机菜单与兰儿的同一组能力调用。

## 本阶段范围

新增 13 项具体滤镜的已声明参数范围内实现：像素化、油画、波浪、小瓷砖、圆角、随机噪点、随机拾取、雨滴、边缘检测、高度转法线、Phong 凹凸、Gaussian 降噪和小波降噪。

ArtFilterRaster 统一输入尺寸与有限浮点检查、内存估算、取消、预乘双线性取样和通道选择。ArtSpatialFilters 接几何与纹理；ArtSurfaceFilters 接导数、法线、照明和降噪。ArtMenuOperations 将它们接到既有选区混合，ArtStore 使用同一菜单分发、版本校验和 MENU_LAYER_CHANGE，lastFilter 保留完整参数。

空间滤镜估算 96 字节／画布像素的工作预算，邻域与变换另有运算量估算。小波还在分配前检查各轴补到 2 次幂后的两个 Double 缓冲。超限明确拒绝，不自动降分辨率。当前仍按整层全画布计算，尚无大图分块。

## 算法与参数边界

- 像素化：画布原点对齐的矩形块，线性预乘 RGBA 平均；边缘按块内实际像素数平均。完整块读完后才混合选区。
- 油画：选择邻域主导亮度桶，取桶内直通 RGB 平均，保留中心 alpha。亮度分桶限定 0–1，颜色平均可保留 HDR；透明邻点不参与，计数使用整数，避免 8 位计数溢出。
- 波浪：正弦／连续三角波控制双轴位移，双线性取样预乘像素；可选边缘重复、环绕、透明。period 为完整周期像素数，phase 为角度，不与 Krita 的 wavelength／shift 数值互换。
- 小瓷砖：按像素面积平均缩图，每轴重复 n 次。砖宽／高向下取整，末尾余数透明，尺寸不足时明确拒绝；选区不改变缩图来源。
- 圆角：像素中心的圆角矩形覆盖率，支持一像素抗锯齿，同时缩放预乘 RGBA；radius=0 为恒等，半径最多短边一半。
- 随机噪点／随机拾取：固定 32 位 seed、画布坐标和流编号决定随机值，同源同参数可复现。噪点是 sRGB 随机色转线性后混合，可写入透明处；拾取使用不可变源的双线性取样。概率和混合度为 0–100 百分比。随机数算法与 Krita 不同，拾取不是其整数坐标采样。
- 雨滴：指数径向折射、非重叠圆形放置、画室自己的边缘光影及 3×3 预乘柔化。number 是数量上限，每滴最多 256 次候选，无可用位置便结束。固定种子可复现；光影不是 Krita 的 8 位角度分区规则，也不将 HDR 先裁为 8 位。
- 边缘／高度转法线：稀疏 Sobel、Prewitt 或中心差分，spacing 是采样间距，不是 Krita 可变卷积核半径。边缘为指定高度通道的灰度幅值、单向分量或方向；法线为归一化的 (-dx×strength,-dy×strength,1)，RGB 可指定轴与符号。保留 alpha，未提供 Krita 的逐 RGB 和透明度边缘模式。
- Phong：最多 4 盏定向灯，环境／漫反射／标准镜面反射，灯颜色与强度可结构化传入。支持高度图或线性 RGB 法线数据、白材质或源色材质，保留 alpha 和 HDR 光强。法线必须在声明范围内且非零；坐标、高光公式和裁限与 Krita 旧实现不同。
- Gaussian 降噪：高斯预乘模糊后，直通 RGB 最大分量差大于阈值时才替换颜色，保留中心 alpha。不是 Krita 的圆形遮罩核和色彩空间色差。
- 小波降噪：各轴补到 2 次幂的矩形正交 Haar，保留最粗低频，对细节做软／硬阈值。阈值为线性 RGB 系数单位，非 Krita 2D 变换的系数尺度；保留原 alpha 和透明位置。threshold=0 直接返回原像素。

导数、油画及降噪仍保留全透明中心的原像素；几何和随机滤镜可以改变透明度。通道开关关闭 alpha 时保留原 alpha，未选 RGB 通道按最终 alpha 重新预乘。所有输出要求有限 RGB ±65504、alpha 0–1。

Krita 参考来自用户指定源码的 pixelizefilter、oilpaintfilter、wavefilter、smalltilesfilter、roundcorners、noisefilter、randompickfilter、raindropsfilter、edgedetection、convertheightnormalmap、phongbumpmap、imageenhancement，并核对 libs/image/kis_math_toolbox.cpp 的小波变换系数。实现采用本文声明的工作模型，不表示完整移植 Qt、Krita 的颜色引擎、随机算法或全部选项。

## 兰儿的入口与可复现调用

本阶段 13 项均写入 ArtStudioMenuCatalog，自动通过已注册的 plugin.art.studio.filter.catalog 返回参数、限制、可用状态及调用模板。无需增加另一个执行分支或单独算法能力。

调用顺序仍为 filter.catalog 查询、menu.preview 只读预览、menu.execute 确认写入，后两者携同一 documentId／expectedRevision。成功后重新读取修订。灯光和轴映射保持 JSON 数组；随机种子进入 lastFilter，重放和重新配置不会偷偷换种子。相同输入、相同参数才保证相同效果，再次应用到已改变的输入当然可能得到不同像素。

例如用 plugin.art.studio.menu.preview 或 plugin.art.studio.menu.execute 传入：

```json
{
  "action": "filter.raindrops",
  "parameters": {
    "seed": 20261031,
    "dropSize": 48,
    "number": 24,
    "fishEyes": 30,
    "lighting": 0.8,
    "blur": true
  },
  "documentId": "DOCUMENT_ID",
  "expectedRevision": 0
}
```

菜单参数元数据以每个参数对象一行存放，使 Filter 菜单的单个 JVM 字符串常量保持在 65535 modified-UTF8 字节以内。现有静态检查增加同一上限检查；此调整不改变已有参数值或调用协议。

## 当前覆盖与剩余机制

具体滤镜 53 项中，开发源码有 48 项提供声明范围内的实现、5 项仍灰显：半色调、索引颜色、扩散颜色、颜色迁移、调色板量化。implemented 不等于所有 Krita 选项或 ICC 数值等价，更不等于设备已部署／运行通过。初始核对文档与第一、二阶段记录保留各自时点的计数。

后续资源与像素机制需要单独接通：

- 半色调对照源码使用可配置图案生成器、强度／独立通道／alpha 模式，不能把任意圆点网格冒充完整机制。
- 索引颜色和调色板量化需要参数化颜色资源、颜色距离和抖动／alpha 规则；颜色迁移需要引用图像的统计数据、有效版本和可重放的配置。下一阶段先核对已有资源机制，再接相应入口。
- Krita 扩散颜色的保留 alpha 模式会在 alpha=0 处写隐藏颜色；画室当前缓冲定义为预乘线性 RGB，alpha=0 的非零 RGB还可表达发光数据。不能把隐藏直通颜色直接写作预乘 RGB，需要独立保真表示及写回语义。
- 前两阶段已经列明的工作模型差异、组内／变换滤镜、资源预设、非破坏滤镜层／滤镜蒙版及 G’MIC 仍未收尾。滤镜库、装饰／非真实感分类占位、两个 G’MIC 入口也仍灰显。完成整轮后再统一推云编译。
