# Protect AI Limbs documents and access context

## Existing behavior

The access prompt and work manual are whole-file editable documents. Reads and writes expose physical paths. The RDC client appends transport instructions directly.

## Intended behavior

- System rules and stable document entry points are generated by code and cannot be replaced through document write APIs
- Editable access, work-manual, and tool-manual bodies remain user controlled
- A changed save archives the previous active body before an atomic replacement
- Each document keeps at most three rotating snapshots
- Restore archives the current body before replacing it
- Access context is assembled in the AI Limbs core and transported by the selected bridge
- Normal UI and bridge responses use document identifiers instead of filesystem paths

## Verification

- Unchanged saves do not create snapshots
- Three snapshots remain after four or more changed saves
- Restore does not require a Terminal or Ubuntu runtime
- System-owned text is absent from editable fields
- Physical paths are absent from the access manager and bridge payloads
