# 视觉 0.2.11 点击后旋转观察竞争修复

0.2.10 配套 build113 的实测中，暂停游戏同一区域的旧 51.4% 误报已连续两次变为 0%，点击约 175–187 ms。两次从桌面点击启动横屏游戏，均成功注入动作；一次观察报 SCREEN_GEOMETRY_CHANGED，一次返回 geometry_changes 并成功稳定。剩余问题位于帧选取与后续状态查询之间的旋转竞争。

## 作用域与修复

只修改视觉插件，升级 0.2.11、versionCode 17、payload v0211，复用 build113 和既有桥。工具入口及默认参数保持兼容，visual_wait 增加 superseded_frames 诊断。

点击后的跟随模式先验证采集会话、生产器和可见性，再比较当前状态与所选帧几何。不匹配的帧不能进入检测器、不能成为返回画面，并使旧稳定窗口失效。下一轮继续已有的有界采样过程，取得一致的新方向帧后建立基准。普通 standalone 等待仍严格绑定原几何。

点击前的旧帧和方向保护不变；观察预算、停止行为及错误边界保留。没有重新注入点击、重新启动采集或重新执行工具；最终没有有效帧时明确报告观察失败。

## 回归与验收

- 帧为旧方向、状态为新方向时，跟随模式剔除该帧；下一帧与状态一致时接纳
- 同一竞争场景下，standalone 模式仍明确报几何改变
- 跟随模式仍拒绝停止、不可见、无帧、错误会话及生产器异常
- 失效观察间隔不能延长旧稳定窗口，恢复后重新等待完整稳定时长

现有 visual-manager-build.yml 执行全部 JVM 测试、assembleDebug、签名及来源记录。源码提交后仅触发一次云端构建，不监测进度；测试和编译结果尚待云端完成。部署后复测桌面至横屏游戏、快速连续旋转和停止期间的观察。
